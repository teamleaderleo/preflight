## Rejected trial and recovery

Ordinary cohort `20260906-031707` failed the criterion. Its first launch reached graphics-ready
in 18.569 s and interactive menu in **20.308 s**, with graceful shutdown and healthy adapter.
The second launch stalled inside native `GL11.nglTexImage2D`, called through the original
TextureLoader from `preflight$commitPreparedResource`; the captured main-thread stack had been
running for 447.92 seconds. No interactive menu was observed. The third launch was cancelled.
The complete planned six-run trial was not continued after failure. There is no sub-18 result
or demonstrated performance improvement from this candidate.

The first log contained 3,745,932 bytes and zero targeted cleanup/rule messages, compared with
8,119,060 bytes in the diagnostic baseline. This confirms the rewrite ran, not that it improved
startup. Similar native upload stalls occurred in earlier experiments, so this observation does
not establish that logging removal caused the stall. The upload checkpoint was off; texture
identity and dimensions of the stalled call are unknown. Do not infer a buffer-lifetime cause.

Captured private evidence: `Diagnostics/windows-sub18/stalled-second-thread-dump.txt`,
`stalled-second-jcmd-error.txt`, and `stalled-second-retirement.json`. Stopped the cohort and
retired game PID 5376 and wrapper PID 1868 after checking exact creation times. A subsequent
recovery attempt (`20260906-033236`) failed before game launch: the original launcher shell
PID 11004 (parent 1868, creation time 1788635893673 ms Unix) remained. The runner correctly
refused to overlap it. Zero Java processes alone was insufficient cleanup evidence. Retired
that exact shell separately; no startup timing is attributed to the failed recovery attempt.

Restored baseline JAR `369d43b415829c5082c29d1762adb9d8fdb73f6cf73d6406087740bd38534cb9`.
Removed the candidate production rewrites and their candidate-specific tests from the final
change; PR history retains the experiment. Existing accepted optimizations remain intact.
Recovery cohort `20260906-034103`, ordinary Recommended, native graphics, 1024x720, two launches
with 20-second cooldown: both accepted. Interactive menus **18.797 / 18.413 s** (median 18.605 s);
graphics-ready **17.738 / 16.690 s**. These are different clocks: the sub-18 graphics observations
do not meet the interactive-menu target. The baseline remains installed. This investigation
does not establish consistent sub-18 startup or justify any new production optimization.

Next investigation should attribute native upload work and the intermittent stall without
adding per-upload file I/O to ordinary launches. Buffer construction has a measured 699 ms bound;
removing that entire cost alone would not reliably close the observed gap, and any reuse needs
the original direct-buffer destruction contract revalidated. Preserve the ceiling, main-thread
GL ownership, coherent fallback and accepted late-resource behavior while testing alternatives.
