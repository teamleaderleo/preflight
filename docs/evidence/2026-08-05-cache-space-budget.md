# Cache space has two different problems

**Date:** 2026-08-05

**Profile:** Starsector 0.98a-RC8, 83 enabled mods, macOS on Apple M5

## Measured footprint

The active Preflight cache occupies 6.9 GB. Its payload is overwhelmingly two deliberate
time-for-space trades:

| category | apparent size | files | representation |
| --- | ---: | ---: | --- |
| prepared textures | 5.0 GB | 30,636 | raw upload-ready RGB/RGBA |
| prepared audio | 1.1 GB | 2,022 | decoded 16-bit PCM |
| generated bytecode | 438 MB | 686 | historical per-request maps plus one deduplicated pack |
| comparison snapshots | 198 MB | 4,928 | benchmark evidence, not a launch cache |
| all remaining cache categories | about 115 MB | | indexes, manifests, spec stores, reports |

The existing safe prune found all 30,636 texture blobs reachable from the current manifest, so the
5.0 GB texture store is not an orphan-collection defect. It is the cost of the fastest exact format.

## Lossless compression probe

Representative largest blobs were compressed and decompressed with native arm64 command-line
tools. These are format-selection measurements, not projected game-launch timings.

| payload | raw | zstd-1 | zstd-3 | LZ4 |
| --- | ---: | ---: | ---: | ---: |
| prepared texture | 40,000,120 B | 8,887,655 B | 8,487,233 B | 13,646,823 B |
| prepared audio | 44,810,424 B | 44,361,753 B | 44,241,512 B | 44,810,483 B |

The texture is 4.5x smaller under low-level Zstandard and decompressed in roughly 30 ms in this
single-file probe. The PCM audio is effectively incompressible. A compact exact texture tier is
therefore plausible; compressed prepared audio is not. The honest audio space choices are selective
preparation or ordinary game decoding, each with an explicit startup/CPU tradeoff.

The already-built selective BC1/BC3 cache remains the more interesting texture endpoint: on the
profile where it was baked, eligible art was 4.51x smaller than raw pixels and its GPU-ready blocks
were projected to load faster while occupying one quarter of the VRAM. It is deliberately lossy,
per-texture fidelity-gated, and still lacks its runtime consumer. It must remain a distinct opt-in
policy rather than silently replacing the exact cache.

## Zero-cost generated-bytecode cleanup

The generated-bytecode directory held three complete compiler contexts of about 146 MB each. The
current context also retained 228 old per-request SPJB bundles after the new 1.2 MB SPJP pack had
deduplicated their repeated class maps.

`preflight cache prune` now computes the exact compiler context for the installed game and mod
profile. It plans removal of other hash-named contexts, and removes an SPJB from the retained context
only after reading both checksummed artifacts and proving the pack contains the same request and
byte-identical complete class map. An unknown live context, unreadable pack, unreadable bundle, or
identity mismatch retains data rather than guessing.

The real dry run now reports **693 files / 505 MB** reclaimable:

- 228 current-context bundles exactly represented by the pack;
- 457 files in two stale compiler contexts;
- 8 old profile/spec artifacts already handled by the prior prune logic.

Nothing is removed without `--yes`, and no texture, audio, current pack, benchmark, or run evidence
is included in this plan.
