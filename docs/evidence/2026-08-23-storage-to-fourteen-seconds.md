# From three-minute preparation to fourteen-second launches

**Date:** 2026-08-23

**Profile:** Starsector 0.98a-RC8, 83 enabled mods, M5 MacBook Air

This note records two different optimization sequences that are easy to conflate. The complete
Preflight stack made a heavily modded launch fast. The later storage work made that result smaller,
quicker to prepare, and in one observed case faster again.

All launch times below use the same clock: Starsector's `Running with the following mods...` log
marker to GraphicsLib's `VRAM after unload/preload` marker. Wrapper lifetime, launcher dwell, UI
automation, and shutdown time are excluded.

## What was already making the launch fast

Compact did not produce the low-15-second launch by itself. It sits on top of the earlier accepted
work:

- prepared upload-ready texture pixels and removal of the serial prefetch wait;
- prepared tagged JSON trees for variants, weapons, projectiles, hulls, rules, and merged readers;
- exact profile-stable JSON routing and shared profile identity;
- prepared audio plus path-indexed, trusted reads;
- packed generated bytecode;
- bounded AshLib, GraphicsLib, MagicLib, Nexerelin, and game-path adapters;
- smaller allocation, copy, path-normalization, logging, and loading-screen seams.

The public component record remains in the [README](../../README.md#where-the-time-went), the
[experiment ledger](../experiment-ledger.md), and the
[accumulated startup scorecard](2026-08-02-accumulated-startup-scorecard.md). Those changes overlap,
so their component timings should not be added together as a whole-launch estimate.

## The three-minute preparation was an implementation mistake

The first pack-producing implementation made every loose prepared-texture input durable on its
own, read all of those files into a pack, forced the pack, reopened and validated it, then deleted
the loose inputs. That meant 14,774 forced files for Compact and 30,638 for Balanced even though
the loose files were rebuildable intermediates.

| Preparation path | Compact | Balanced |
| --- | ---: | ---: |
| Per-file durable intermediates | 92.30s | 198.56s |
| Double workers and memory | 92.45s | not measured |
| Rebuildable intermediates, final pack forced once | 16.51s | 44.62s |
| Current consuming pack publication | **17.25s** | **38.33s** |

More workers and memory did nothing. Publication dominated. Current preparation validates each
complete intermediate while streaming it into the pack, releases it when safe, then forces,
reopens, and validates the single finished pack before activating it.

This also removed the finished-directory duplication. Balanced fell from about 4.76 GB to 2.3 GB.
Compact retains about 1.1 GB. The detailed safety and free-space boundary is in
[Compact preparation and intermediate publication](2026-08-23-compact-preparation-and-intermediate-publication.md).

## Compact and physical order

Compact retains the textures observed during one real launch: 16,013 logical paths representing
14,774 distinct source images. The resulting pack is 1,087,894,442 bytes.

Logical contents alone were not sufficient. The same Compact corpus written alphabetically launched
in 33.53 seconds. Writing it in observed access order launched in **14.174 seconds**, with 15,469
prepared hits, three ordinary source fallbacks, and no pixel-conversion fallbacks. Reordering an
existing pack took 2.02 seconds. Physical order is therefore part of the prepared-pack performance
contract.

Current code exposes Compact only after a successful launch has recorded the required access set.
Safe source fallbacks still handle a later path that was not in the learned pack.

## The 13.69-second JVM result

A separate candidate campaign compared the then-current fast path with the reviewed macOS Rosetta
collector and heap policy. Each condition had five exact-marker launches with 240 seconds of
cooldown between launches.

| Condition | Samples | Median | Best |
| --- | --- | ---: | ---: |
| Current fast condition | 16.25, 16.61, 15.97, 15.90, 15.76 | 15.97s | 15.76s |
| Reviewed G1 and deferred heap-commit condition | 15.10, 14.04, 14.20, 13.80, 13.69 | **14.04s** | **13.69s** |

The summary identifies candidate JAR
`f0c5245160bbb9f7aa9d9ba9c07229414200b7afccb294ab66954ce1ab9f1f45` and repository snapshot
`829c52c571376e568004768726600b01ec2282ed`. Its checked summary is retained locally at
`~/.starsector-preflight/benchmarks/20260823-083700/benchmark-summary.json`, SHA-256
`36ee8efe436772402b03c1cb9e92360289e1b8503b5f41535f72f61eaaee767f`.

The reviewed policy became the current macOS Rosetta path: G1, Shenandoah disabled, and heap commit
deferred instead of touching the complete configured heap before launch. Other platforms keep their
launcher policy.

Later one-run exact observations on the current texture path recorded:

| Storage state | Exact startup |
| --- | ---: |
| Balanced, summary `bba6eaf4...38d45` | 15.49s |
| Compact, summary `c57d5fd9...1277d` | **14.49s** |
| Current path after pack publication changes, summary `0d7bf5ef...9790` | **14.84s** |

These single observations establish that the current code retained the fourteen-second regime. They
are not a replacement for a release-candidate campaign.

MagicLib's paintjob catalog was the next measured callback reduction. Its loader moved from 650 to
52 milliseconds on a direct miss/hit comparison. That is the latest chapter, not the explanation
for the earlier fourteen-second results.

## Why Balanced still exists

Balanced is the current bootstrap default because a fresh profile has no observed startup access
set. It prepares the complete reviewed texture corpus and works before any learning launch.

Compact is the better measured steady state on this profile. It retains less than half the texture
data, prepares in less than half the time, and produced the faster whole launch. The intended product
policy is therefore **Automatic**:

1. start a new profile with complete coverage;
2. observe a successful launch;
3. build and validate Compact while idle or after exit;
4. activate it only after the complete pack passes its identity and health checks;
5. keep ordinary source fallback and the previous valid pack as recovery paths.

That automatic graduation is tracked in
[#1084](https://github.com/teamleaderleo/preflight/issues/1084). Until it lands, Balanced remains the
fresh-profile default and Compact remains an explicit post-observation choice. Minimal remains the
low-space option, and Uncompressed remains an advanced experiment with no established whole-launch
advantage.
