# Issue #1153: GraphicsLib packed tessellation replay

This is an incremental experiment on top of the `GraphicsLibTessellateArrayPlan` candidate.

## Prior-art link

Fast Rendering does more than replace immediate-mode vertex calls with `glDrawArrays`: it records primitive vertex attributes into primitive buffers and reuses those buffers for later submission. Its selected reorder path also accumulates compatible vertices and commits them in larger array draws.

The first Preflight GraphicsLib candidate already removes the per-vertex `Vector2f` allocation, repeated ship accessor/trig work, and `glVertex2f` native calls. Its remaining cached replay still walks `List<VertexDataV2>`, loads each `double[] data`, casts X/Y to float, and calls `FloatBuffer.put(float)` twice per vertex every frame.

## GraphicsLib lifetime proof

Reviewed GraphicsLib 1.12.1 source stores one `TessData` in a `WeakHashMap<ShipAPI,TessData>`.

`TessData.vertices` is populated only while GLU tessellation callbacks build that object. A later bounds checksum mismatch removes the entire `TessData` and creates a fresh one. The normal cache-hit branch reads the list but does not mutate it.

That gives the local tessellated X/Y coordinates the same lifetime as the `TessData` object itself. A cache keyed by that object can therefore pack `(float) data[0], (float) data[1]` once and discard the packed coordinates automatically when the owning `TessData` becomes unreachable.

## Candidate

Property:

```text
-Dpreflight.graphicsLibTessellatePackedReplay=true
```

The property only takes effect when `preflight.graphicsLibTessellateArray=true` is also enabled.

`GraphicsLibTessellatePackedReplayPlan` is a second exact bytecode pass over the helper generated by the reviewed array candidate. It requires the expected helper, exactly two scalar `FloatBuffer.put(float)` calls, one `flip`, one `List.iterator`, and one `Iterator.hasNext`/draw exit. It then inserts a shortcut before the original iterator.

The shortcut calls `GraphicsLibTessellateArrayRuntime.fillPacked(...)` with:

- the current `TessData` identity;
- the existing direct vertex buffer;
- the already-computed float cosine/sine values;
- the already-read ship X/Y location.

On the first encounter with a `TessData`, the runtime reflectively reads the public GraphicsLib `vertices` and `data` fields and builds one primitive local `float[]`. Later encounters reuse it. The cache is a render-thread-local `WeakHashMap<Object,float[]>` so it does not keep retired `TessData` objects alive.

World-space output uses a thread-local primitive scratch array and preserves Candidate 2's float arithmetic order:

```text
worldX = x * cos - y * sin + locationX
worldY = x * sin + y * cos + locationY
```

The world array is copied into the existing direct `FloatBuffer` in one bulk `put` before the unchanged `flip`/client-state/VBO-safe `glDrawArrays` path.

## Failure behavior

The original Candidate 2 list/iterator replay remains in the transformed helper.

If packed replay is disabled, misses its exact bytecode gate, cannot read the expected public fields, sees invalid data, or hits another runtime failure, the shortcut returns false with the direct buffer cleared and execution falls through to that reviewed list replay.

This makes primitive packing an independent optional hot-path shortcut rather than a new rendering dependency.

## Causal telemetry

The existing GraphicsLib candidate report adds:

- `packedReplayEnabled`;
- `packedCacheHits` / `packedCacheMisses` / `packedCacheBuilds`;
- `packedFailures`;
- `packedReplayBatches` / `packedReplayVertices`;
- `packedFloatsBuilt`;
- `worldScratchGrows` / `largestWorldScratchFloats`.

A healthy long combat should show cache builds bounded by the number of live/rebuilt tessellations, hits growing with repeated rendering, failures at zero, and replay batches tracking the array candidate's batch count after warmup.

## Measurement

Use the dedicated pair so array conversion is held constant:

```bash
scripts/run-1153-render-pilot.sh \
  --experiment tess-packed \
  --variant baseline \
  --route ordinary \
  --workload-id <same-id>

scripts/run-1153-render-pilot.sh \
  --experiment tess-packed \
  --variant candidate \
  --route ordinary \
  --workload-id <same-id>
```

Repeat on `symmetric-1040` if the ordinary pair is healthy. Compare with `scripts/compare-1153-render-pilots.sh`.

Retention requires useful p95/p99/1%-low or severe-frame improvement, zero visual/stencil regressions, zero packed failures in the measured route, and enough `packedReplayVertices` to demonstrate that the shortcut actually carried meaningful work.
