# Preflight 0.1.0

Preflight 0.1.0 is the first public beta of a free, open-source performance launcher and companion app for Starsector. It prepares repeatable startup work ahead of launch, reuses it while the game and mod inputs still match, and lets Starsector do the work normally when something has changed.

> Preflight is an independent, unofficial project. It isn't affiliated with or endorsed by Fractal Softworks.

These notes describe the product facts known before the release tag is created. After tagging, the release process runs its package lifecycle, packaged startup benchmark, and report-intake checks against the tagged candidate itself; those results are recorded separately and must pass before publication.

## Performance

On the reviewed 83-mod development installation, the latest same-profile controlled comparison measured:

- **89.00-second median** across five ordinary launches;
- **15.53-second median** across five Preflight launches in the same session;
- **15.25 seconds** for the lowest recorded Preflight launch in that comparison;
- roughly **101 seconds** as an earlier observed development high.

The two launch paths were interleaved, the machine cooled for 240 seconds before each launch, and all ten results stayed in the comparison. Those numbers describe one M5 MacBook Air, one 83-mod profile, Starsector 0.98a-RC8, and the stated development runtime conditions; the tagged package gets its own retained startup benchmark before publication.

The desktop includes the same normal-versus-Preflight benchmark so each installation can measure its own result. **Copy result** produces a compact shareable comparison without private paths or the full run record.

## What is included

### Prepared startup work

Recommended mode and Balanced storage are the defaults. Preflight can prepare reusable texture, data, generated-code, and audio work before Starsector launches. Matching work is reused automatically; when something has changed, is damaged, or is unfamiliar to the current release, Starsector handles that work normally.

The three user-facing optimization levels are:

- **Recommended** — the reviewed optimizations available for the current installation;
- **Conservative** — broad startup caches while leaving out the more specialized runtime shortcuts;
- **Off / troubleshooting** — turns runtime optimizations and profiling off while profiles, settings, support, and the rest of the launcher remain available.

### Named mod profiles and launch settings

Profiles can be created, searched, switched, renamed, duplicated, and deleted. Switching shows which mods will change and saves a backup before applying the new selection.

Resolution, fullscreen, sound, antialiasing, UI scale, RAM, and battle size are available beside Launch. Memory changes follow the selected launcher, keep a backup, and stop when Preflight cannot identify one clear settings file to edit.

### Storage planning, cleanup, and recovery

Before preparation, Preflight calculates how much additional storage the current profile is expected to need, how much room to reserve, what reusable data is already present, and whether the preparation fits on the selected disk.

Cleanup is preview-first and keeps the current profile and readable named profiles available. Starsector, mods, and saves stay outside the cleanup target. Preparation can stop safely; completed reusable work remains available, while a new prepared profile only becomes active after preparation finishes.

### Playtime and launch history

Preflight keeps local play history for sessions it launches and can observe. That history is separate from the larger diagnostic run directories, so old diagnostics can be cleaned up without forgetting that a launch happened. Older Preflight launches can be imported when enough information is available, and an interrupted session can be recovered when the stored process information clearly identifies it.

### Read-only setup analysis

`preflight lint` reports measurable asset and configuration problems without editing the installation or assigning a score. `preflight scan` inventories the enabled profile. The deeper setup analysis can report missing or malformed mod metadata, duplicate IDs, missing or disabled required dependencies, and resolved variants whose declared hull is absent from the active profile.

### Privacy-conscious support

**Copy setup** produces a small support summary with useful game, profile, mod, and launch facts while leaving out private paths, credentials, save contents, and arbitrary logs.

The separate support ZIP uses a fixed list of allowed diagnostic files and explicit size limits. It excludes acceleration caches, Starsector and mod files, saves, screenshots, audio, arbitrary logs, crash dumps, JFR recordings, credentials, and unknown files. Where report sending is enabled, the desktop shows the ZIP before sending, supports cancellation and retry, and keeps the accepted case receipt and deletion option available afterward.

Automatic failed-run reporting is a separate remembered setting and starts off.

### Signed updates and rollback

Supported desktop packages use one release feed. When a newer version is available, the user reviews it and chooses **Install and restart**; Preflight checks that the offer is still the one the user reviewed and verifies the updater signature before installation.

Cache formats that cannot be shared between releases use separate locations, so rolling the application back does not first destroy the prepared data the older version understands. Linux `.deb` installations remain managed by the package manager.

## Packages and release trust

The first beta targets:

- **Windows x86-64** — `Preflight-Windows-x86_64.exe` (NSIS installer);
- **macOS Apple silicon** — `Preflight-macOS-arm64.dmg`;
- **Linux x86-64** — `Preflight-Linux-x86_64.AppImage` and `Preflight-Linux-x86_64.deb`;
- the standalone `preflight.jar`, `.zip`, and `.tar.gz` distributions.

Native packages include the minimal Java runtime used by Preflight. Starsector and Fast Rendering continue to use their own runtime.

The complete distribution also carries SHA-256 manifests, dependency inventory, target-specific CycloneDX SBOMs and their checksums, license and third-party notices, privacy information, known limitations, updater artifacts, and the fixed update manifest.

The first beta does not use paid Apple Developer ID or Windows Authenticode publisher identities, so macOS and Windows can show their normal unknown-developer warnings. Preflight's updater signature is separate from those platform publisher identities.

Creating the release tag produces the draft release and candidate packages. The remaining package lifecycle, packaged benchmark, report-intake, and release checks then run against those tagged files, and publication uses those accepted files rather than rebuilding them later from the same source revision.

## Known beta limits

- Real-game testing has been deepest on Apple silicon macOS. Windows and Linux have substantial automated package coverage; the first beta is published only after the required real-game Windows and Linux installation exercises complete.
- There is no Intel Mac package in the first beta.
- The reviewed game version is **0.98a-RC8**. Other versions may use fewer optimizations until changed targets are reviewed.
- The development performance numbers above describe the stated machine and 83-mod profile; other installations can differ substantially.
- First preparation can take several minutes and gigabytes on a large profile. The app calculates the local requirement before starting.
- When game or mod code changes, an affected runtime optimization can step aside and let Starsector handle that work normally until the new version is reviewed.

See [Known limitations](../known-limitations.md) for the complete list and [Release readiness](../release-readiness.md) for the remaining release checks.
