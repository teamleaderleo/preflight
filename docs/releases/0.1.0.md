# Preflight 0.1.0

Preflight 0.1.0 is the first public beta of a free, open-source fast launcher for Starsector.

> Preflight is an independent, unofficial project. It isn't affiliated with or endorsed by Fractal Softworks.

These are tag-owned release notes. They contain facts that are knowable before the release tag is created. Package-dependent lifecycle, startup-benchmark, and report-intake evidence comes from the exact tagged candidate afterward and is reviewed separately before publication.

## Performance

On my 83-mod M5 MacBook Air development setup, startup moved from **112.17 seconds to 13.69 seconds**, about an **8.19× speedup**. Starsector's bundled x86-64 Java runtime is running through Rosetta on that machine.

That is a development result, not a promise about the tagged package or another installation. The release gate separately requires a startup benchmark through the verified engine extracted from the exact tagged candidate package.

The desktop includes its own normal-versus-Preflight benchmark so you can measure your installation. **Copy result** produces a compact shareable comparison without raw evidence or private paths.

## What is included

### Fast launch

Recommended mode prepares and reuses matching texture, data, generated-code, audio, and related startup work. A fresh profile starts with complete Balanced texture coverage; after one successful launch, Preflight learns the access order and prepares the smaller Compact steady state during a later idle window.

Runtime shortcuts and prepared data are tied to the inputs and code they expect. If one does not match, it steps aside and the normal game path runs.

The three optimization levels are:

- **Recommended** — every optimization enabled for the exact inputs it recognizes;
- **Conservative** — broad immutable-input startup caches without the more specialized runtime shortcuts;
- **Off / troubleshooting** — runtime transformations and profiling disabled while the launcher and surrounding desktop tools remain available.

### Tracked playtime!!!!!

Preflight keeps a local launch/playtime history for Starsector sessions it starts and can observe, including sessions that continue after the desktop minimizes or exits. The history can be exported as versioned JSON and spreadsheet-safe CSV.

### Launch settings

Resolution, fullscreen, sound, antialiasing, UI scale, RAM, and battle size are available beside Launch.

Battle size uses Starsector's own `battleSize` preference and can be set through **2,147,483,647 deployment points** (`INT32_MAX`). The ordinary shortcuts still include values such as 600, 1000, 1500, and 2000.

Memory changes follow the selected launcher to one unambiguous launcher-owned settings file and keep a backup. Ambiguous layouts are refused instead of guessed.

### Setup checks and mod tools

Preflight can check the active setup for missing or malformed mod metadata, duplicate IDs, missing or disabled required dependencies, and selected resolved-reference problems without starting Starsector.

`preflight lint` reports measurable asset and configuration findings for one mod or a full profile. `preflight scan` inventories the enabled profile.

### Storage planning, cleanup, and recovery

Before preparation, Preflight calculates the current installation's temporary and finished storage requirement, free space, compatible retained data, and reusable current-profile artifacts.

On the 83-mod development setup, learned Compact data settles around **1.1 GB**. First preparation needs more working room; the app calculates the actual requirement before it starts writing.

Cleanup is preview-first. Starsector, mods, and saves are outside the cleanup target. Preparation can stop safely; completed immutable work remains usable, while an incomplete new manifest is never activated.

### Saved launch profiles

Preflight can save, search, switch, rename, duplicate, and delete named launch profiles. Switching previews the enabled-mod change and saves a backup before applying it. Preflight does not install or update mods.

### Hangar

The desktop can read installed hull definitions and locally trace installed ship sprites into Preflight's wireframe presentation. The package does not ship Starsector ship artwork.

### Support

**Copy setup** produces bounded support text without paths, credentials, save contents, or arbitrary logs.

The separate support ZIP uses a fixed allowlist and explicit size limits. It excludes acceleration caches, Starsector and mod files, saves, screenshots, audio, arbitrary logs, crash dumps, JFR recordings, credentials, and unknown files. Where the release intake is enabled, the desktop shows the ZIP before sending and supports cancellation, retry, receipts, and deletion.

The first beta sends no failed-run report automatically.

### Signed updates and rollback

Supported updater packages use one fixed release feed. The user reviews a newer release and chooses **Install and restart**; the exact reviewed offer is rechecked and the updater signature is verified before installation. Cache formats use versioned namespaces so rollback can keep the representation an older application expects.

Linux `.deb` installations remain package-manager-managed.

## Packages and release trust

The first beta targets:

- **Windows x86-64** — `Preflight-Windows-x86_64.exe` (NSIS installer);
- **macOS Apple silicon** — `Preflight-macOS-arm64.dmg`;
- **Linux x86-64** — `Preflight-Linux-x86_64.AppImage` and `Preflight-Linux-x86_64.deb`;
- standalone `preflight.jar`, `.zip`, and `.tar.gz` distributions.

Native packages include the minimal Java runtime used by Preflight. Starsector and Fast Rendering continue to use their own runtime.

The complete Distribution set also carries SHA-256 manifests, dependency inventory, target-specific CycloneDX SBOMs and their checksums, license and third-party notices, privacy information, known limitations, updater artifacts, and the fixed update manifest.

The first beta does not use paid Apple Developer ID or Windows Authenticode publisher identities, so macOS and Windows can show their normal unknown-developer warnings. Preflight's updater signature is separate from those platform publisher identities.

Creating the tag produces a draft release and the exact candidate bytes. Package lifecycle, exact packaged-engine benchmark, report-intake canary, and the remaining release checks are then run against those tagged bytes. Publication uses that already-created draft and its verified assets; a rehearsal candidate or rebuild from the same source revision is not the final package authority.

## Known beta limits

- Real-game testing has been deepest on Apple silicon macOS. The first beta is published only after the required real-game Windows and Linux installation exercises complete.
- There is no Intel Mac package in the first beta.
- The reviewed game version is **0.98a-RC8**. Other versions may receive fewer optimizations until changed targets are reviewed.
- Development performance numbers describe the stated machine and mod profile. Other installations can differ.
- Runtime shortcuts are exact-gated. A changed or unknown target loses that optimization and keeps the original game behavior.

See [Known limitations](../known-limitations.md) for the complete list and [Release readiness](../release-readiness.md) for the release-evidence checklist.
