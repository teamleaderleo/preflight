# Draft release notes — 0.1.1-rehearsal is not a release

This version is never tagged, never built for anyone, and never published. It exists so the package
lifecycle rehearsal has a second version to upgrade to and roll back from.

`set-release-version.mjs` refuses to move the project's version strings unless reviewed notes exist
for the target version, and the lifecycle rehearsal needs two packages whose versions differ — a
"upgrade" to the same version installs nothing and would prove nothing. Rather than let CI write its
own placeholder notes and hollow out that gate, the rehearsal's version is declared here, in the
open, with what it is.

The "Draft release notes" line above is load-bearing. `validateReleaseNotes` rejects it for any
public tag and permits it only on a `workflow_dispatch` run that isn't a tag, so a `v0.1.1-rehearsal`
tag fails the distribution workflow instead of publishing this file as release copy.

Nothing about the product changes at this version. See
[Package lifecycle rehearsal](../package-lifecycle-rehearsal.md) for what the run checks.
